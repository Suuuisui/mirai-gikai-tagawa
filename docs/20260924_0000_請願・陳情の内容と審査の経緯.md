# 請願・陳情の「要望の内容と理由」と「審査の経緯」

## 背景

`/petitions` は公式サイトの審査状況・審査結果の表を機械的に整理したもので、件名・付託先・結果は分かるが「何を求め、なぜ出されたのか」「委員会でどう審査され、なぜその結果になったのか」が読み取れなかった。「請願の理由も分かると嬉しい」という声への対応。

## 変更

### 1. 要望の内容と提出者が挙げる理由（原文があるものだけ）

- 公式サイトに原文（PDF）が載っている請願・陳情について、原文を読んで平易に書き直したものを `web/src/features/petitions/shared/data/petition-notes.ts` に置く（`gist` = 何を求めているか、`reasons` = 提出者が挙げる理由、`councilOpinion` = 採択にあたり議会が付した意見）
- 主張は提出者の主張として「〜としている」「〜と訴えている」と書き、評価は加えない。原文に無いことは書かない。提出者の個人名は書かない
- 2026-09-24 時点で原文があるのは令和5年5月以降の 7 件と、附帯意見の 2 件。古い請願・陳情は公式サイトに原文が無いため載せない
- テスト `petition-notes.test.ts` が id の存在・重複・文字数を確認する

### 2. 審査の経緯（委員会の記録との照合）

- 委員会の記録（`committee_meetings`）の議題と要点だけを取る軽量キャッシュ `getCommitteeMeetingPetitionRefs()`（キー `committee-meeting-petition-refs`、タグ `committee-meetings`、1時間）を新設
- 純粋関数 `matchPetitionMeetings()`（`shared/utils/petition-meetings.ts`）が、上程日の少し前から結果が出た日の少し後まで（審査中・継続審査は上限なし）の会議のうち、議題か要点で触れているものを古い順に返す。触れているかは「件名そのもの」「番号（陳情第2号）＋件名の語」「件名の語＋『陳情／請願』」のいずれかで判定する。番号は年ごとに 1 から振り直されるので単独では使わない
- 会議が審査したと分かっていれば、要点は番号だけの言及（「陳情第2号は継続審査」）も拾って、審査の結果や理由としてカードに載せる
- カード（`PetitionCard`）に「要望の内容」「提出者が挙げる理由」「採択にあたり議会が付した意見」「審査の経緯（委員会の記録から）」を追加。会期まとめの小さいカード（compact）には載せない

## 運用

- 新しい請願・陳情が出たら、公式サイトの原文 PDF を `pdftotext -layout` で読み、`petition-notes.ts` に追記する（自動更新の Issue には載らないので、`/petitions` の審査中の一覧を見て気づく）
- 審査の経緯は委員会の記録を取り込むだけで自動的に増える
