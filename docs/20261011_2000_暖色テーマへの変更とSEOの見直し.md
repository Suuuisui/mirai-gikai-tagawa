# 暖色テーマへの変更と、SEO の見直し（2026-10-11）

運営者の指示「色を暖色に戻してほしい。デザインを見直してほしい。あと SEO」への対応。

## 1. 配色: 炭坑レンガの赤茶を軸にした暖色

2026-08-26 のデザイン刷新でデジタル庁デザインシステム（DADS）の青（`#0017c1`）にしていたキーカラーを、
当初の炭坑レンガの赤茶に戻した。**青には戻さない**。
白い背景・罫線・角丸・見出しの形と、文字サイズ・余白・コントラストの考え方は DADS のまま。

### 色の決まり（`web/src/app/globals.css`）

| 役割 | 値 | 白地でのコントラスト |
| --- | --- | --- |
| キーカラー `--primary` | `#b5432a` | 5.5:1 |
| 濃いキーカラー `--primary-accent`（リンク・強調の文字） | `#8f2f1c` | 8.1:1 |
| 本文の文字 `--color-mirai-text` | `#231f1c` | — |
| 補足の文字 `--color-mirai-text-muted` | `#675f59` | 6.3:1 |
| キーカラーの薄い面 `--color-mirai-surface-key` | `#fbeee7`（上に載せる `primary-accent` は 7.1:1） | — |
| ふつうの面 `--color-mirai-surface` | `#f6f2ed` | — |
| 罫線 `--color-mirai-border` / `-muted` | `#d6cec5` / `#e9e3db` | — |

- 文字・面・罫線は、少し赤みのある暖かい灰色にそろえた。Tailwind 既定の `gray-*` は青みがあるので、
  `@theme` で同じ明るさの暖かい灰色に置き換えている（`text-gray-500` は `bg-gray-100` の上で 4.9:1）
- **意味を持つ色は変えていない**: 賛否（賛成＝緑、反対＝赤）、出典バッジ（公式＝青、文字起こし＝黄、開示請求＝紫）。
  出典バッジの青は「キーカラー」ではなく「公式の資料」を表す色として残している
- グラフは、注目＝`bg-primary`、同じ棒の残り＝`--color-mirai-chart-remainder`（`#d98b74`）、比較＝灰色の 3 つだけ
- 議案カバーの 6 系統（terracotta / slate / sage / ochre / brown / beige）× 濃淡 3 段は `--color-cover-*`

### 色を直接書いている場所（`globals.css` を変えただけでは変わらない）

色を変えるときは、ここも合わせて直す。

- `web/src/app/layout.tsx` … `themeColor`、`NextTopLoader` の `color`
- `web/public/manifest.json` … `theme_color`
- `web/src/app/api/og/bills/[billId]/cover-colors.ts` … 議案の共有画像（`BillCover` の複製）のカバーの色・文字の色。
  `cover-colors.test.ts` が `globals.css` の値と突き合わせるので、片方だけ変えるとテストが落ちる
- `web/src/app/api/og/report/route.tsx` … レポートの共有画像
- `web/public/img/logo.svg`・`service-logo.svg`・`hero-symbol.svg`、`web/public/icons/*.svg`

`web/public/ogp.jpg`・`favicon.ico`・PWA アイコンと管理画面は、当初の暖色のままだったので触っていない。

## 2. デザインの見直し

- **議案カードを詰めた**: カバーの高さを 144px → 96px（PC は 176px → 112px）、題名を 1 段小さくした。
  トップページはスマホで約 700px 短くなり、1 画面に入る議案が増えた。
  「注目」の印は、低くなったカバーで「議案」「認定」の文字に重なるため右上へ移した
- **議案詳細の見出しカバー**: 一覧と同じ部品（`BillCover`）に `hero` を足し、番号とアイコンを大きくして左下に寄せた。
  高さは 288〜320px → 256px。スマホではカバーの上がヘッダーの下に入るので、文字を下に寄せると必ず見える位置に来る
- **議案の共有画像の日付の語**: 画面と同じく、議決済みは「議決」、会期中は「提出」と出す（これまで常に「提出」だった）
- 利用規約・プライバシーポリシーの見出しと本文が青みの灰色（`slate-*`）だったので、共通の文字色のトークンにした
- 選挙ページの注記「濃い青／明るい青」は、色名を書かず「濃い色／明るい色」にした

## 3. SEO の見直し

本番の全 996 ページを取り出して、題名・説明・共有情報・構造化データを集計したうえで直した。

### 見つかった問題と対処

| 問題 | 対処 |
| --- | --- |
| 議案詳細 642 件のうち 246 件で `<title>` が他の議案と同じ（例:「令和3年度田川市一般会計補正予算」が 11 件） | 同じ題名が他にもある議案だけ、「（議案第1号・令和3年3月19日議決）」のように番号と日付を添える（`bill-seo.ts`）。h1 と Article の headline は元のまま |
| 一覧ページ（検索・会期・過去の会期・議員・委員会・一般質問・請願）の共有題名がサイト共通のまま、`og:url` が無い | `buildPageShareMetadata` でページごとの題名・説明・URL を出す |
| 議案のトピック・インタビュー・レポートのページに `og:site_name`・`og:url` が無い | 同上 |
| 説明文が短すぎる・長すぎる（利用規約 14 字、タグ 17〜31 字、委員会記録は 160 字でぶつ切り） | 固定ページは 80〜120 字の文言を `lib/seo/page-copy.ts` に置き、テストで長さを守る。委員会記録は要約を文の切れ目で切る（`lib/seo/page-description.ts`） |
| 委員会記録の詳細に Article の構造化データが無い、題名が見出しだけ | Article（公開日・更新日つき）を出し、題名を「見出し｜田川市議会 会議名（令和8年10月8日）」にした（`committee-seo.ts`） |
| パンくずが 2 段（TOP > 議案） | 議案詳細は「TOP > 会期のまとめ > 議案」、会期のまとめは「TOP > 議会ごとのまとめ > 会期」の 3 段に |
| sitemap の `lastModified` が「いまの時刻」で埋まっていた | 載っているデータの更新日から求め、無ければ省く（`lib/seo/sitemap-entries.ts`）。通告にある予定の質問日など、今日より後の日付は使わない |
| 検索結果（`/search?q=…`）や中身の無いトピック・回答一覧が index されうる | `/search?q=…` はミドルウェアで `X-Robots-Tag: noindex, follow`、データが空のページと `/report/*/complete` は noindex |
| 運営者の構造化データが無い | トップに Organization を追加 |

### 守ること

- ページの共有情報は必ず `buildPageShareMetadata`（`web/src/lib/seo/share-metadata.ts`）で作る。
  ページで `openGraph` を直接書くと、ルートの共有画像 `/ogp.jpg` が消える。
  `share-metadata-usage.test.ts` が、検索に出るページでの使い忘れと `openGraph` の直書きを検出する
- 新しいルートを足したら sitemap に載せるか、載せない理由を `web/src/app/sitemap-coverage.test.ts` に書く
  （載せ忘れはこのテストが落ちて気づける）
- 固定ページの説明文は `page-copy.ts` に足す（80〜120 字）。画面の文言と食い違う主張を書かない
- 議員ページの説明には「賛否の数は評価を示すものではありません」を添える（編集方針）

### 見送ったもの（効果が大きい順）

1. 委員会記録の内部リンク: `/committees` の HTML に出る会議へのリンクは 201 件中 36 件
   （委員会ごとに 3 件。残りは「残り N 回を見る」を押した後にしか出ない）。全件を HTML に出すか、年別のページを作る
2. 傍聴・議会日程の案内、「百条委員会とは」のような用語の解説ページ（検索されやすいが、新しいページが要る）
3. HTML が重いページ（`/proposers/mayor` 約 1.6MB、`/sessions/{id}` 約 470KB）の分割・遅延読み込み
4. 議案詳細の説明文（最大 160 字）を 120 字前後に
5. WebSite の構造化データをトップだけにして Organization と `@id` で結ぶ、`/sessions` と `/archive` の役割の整理
