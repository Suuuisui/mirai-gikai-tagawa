# 委員会記録機能: 情報開示請求文書とYouTube字幕の統合

## 背景

田川市議会の委員会（常任委員会・特別委員会）の議事録は公式には公開されていない。
運営者が情報開示請求を行い一部の議事録を入手したが、開示されたのは以下のみ:

- 総務文教委員会: 令和3年1月〜令和4年3月の12回分
- 指名競争入札による建設工事発注に関する調査特別委員会（百条委員会）: 令和7年9月〜令和8年2月の4回分

開示されなかった期間・委員会は、公式YouTubeチャンネル（田川市議会中継）の
中継動画の自動字幕をテキスト化して補完する。

## データソース

| 出典 | source_type | 範囲 |
| --- | --- | --- |
| 情報開示請求で入手したPDF（議事録・概要・記録・議題） | `disclosure` | 総務文教12回 + 入札百条委4回 |
| 公式YouTube中継の自動字幕（ja-orig） | `youtube` | 委員会系動画 約83回分（議会運営・総務文教・厚生・建設経済・一般廃棄物特別委・公選法検証特別委・個人情報漏えい調査特別委・全員協議会等） |

- 同一会議が両方に存在する場合は開示文書（disclosure）を正とし、YouTube版は
  投入せず開示レコードの `youtube_url` に中継URLを紐づける。
- 一般質問・本会議の動画は、本会議録が公式の会議録検索システムで公開されている
  ためスコープ外。

## スキーマ

`committee_meetings`（マイグレーション: `20260828120000_add_committee_meetings_table.sql`）

- 会議1回 = 1行。`(committee_name, meeting_date, source_type)` で一意（upsert可能）
- `summary` / `key_points` / `agenda_items` / `attendees` はAIによる整理結果
- `minutes_text` に原文テキスト（PDF抽出 or 字幕起こし）を全文保持

## パイプライン

1. **開示PDF**: Google Drive（開示結果フォルダ）から Drive API でテキスト抽出 →
   会議単位のJSONに構造化（要点・要約はAIが議事録全文から生成）
2. **YouTube**: `yt-dlp --flat-playlist` でチャンネル全動画を列挙 → タイトルから
   開催日・委員会名をパース → `--write-auto-subs --sub-langs ja-orig` で字幕取得 →
   VTTをテキスト化（ロールアップ重複除去）
3. **AI整理**: `web/scripts/summarize-committee-meetings.mjs` が AI Gateway
   （google/gemini-3-flash）で summary / key_points / agenda_items / attendees を生成
4. **投入**: `scripts/import-committee-meetings.mjs` が中間JSONを
   `committee_meetings` へ upsert

## 表示

- `/committees` 委員会別グループの一覧（出典バッジ付き）
- `/committees/[id]` 概要・要点・議題・出席委員・中継リンク・記録全文（折りたたみ）
  - 出典と「AIによる整理であり原本を確認すべき」旨の注意書きを必ず表示する

## 運用メモ

- 新しい中継動画が公開されたら手順2〜4を再実行すれば追記される（upsertのため冪等）
- 追加の開示文書を受領したら手順1のJSONを作り直して再投入する
- 本番投入は本番Supabaseの `SUPABASE_URL` / `SUPABASE_SECRET_KEY` を環境変数に
  与えて手順4を実行する
