# 委員会ごとの記録ページ（2026-10-11）

SEO の見直し（`docs/20261011_2000_暖色テーマへの変更とSEOの見直し.md`）で見送った項目の 1 つ目、
「委員会記録への内部リンク」への対応。

## 何が問題だったか

`/committees`（委員会の記録の一覧）は、委員会ごとのカードに最新 3 件だけを出し、
残りは「残り N 回の記録を見る」ボタンを押した後にブラウザ側で描画していた。
そのため HTML に出る会議ページへのリンクは **201 件中 36 件**だけで、
残りの会議ページは sitemap と前後ナビでしかたどれなかった。

## 作ったもの

委員会ごとのページ `/committees/group/[slug]`。その委員会の全会議を、年ごとに新しい順で並べる（サーバー描画）。

| 部分 | 中身 |
| --- | --- |
| 見出しの帯 | 種別（常任委員会 / 特別委員会 / その他の会議）、「○○の記録」、委員会の説明、回数、開催期間、出典の内訳 |
| 年のジャンプナビ | 「2026年（9）」のように年と件数 |
| 年ごとの一覧 | 「2026年（令和8年）」の見出しと、その年の会議（見出し・日付・テーマ・出典バッジ） |
| ページの末尾 | ほかの委員会・会議の記録へのリンク（種別ごと・件数つき）、一覧へのリンク、パンくず |

- 13 の委員会・会議のページから、全 201 会議へのリンクが過不足なく出る（dev で数えて確認）
- 題名は「田川市議会 ○○の記録（N回）」、説明は 80〜120 字（`committee-seo.ts`）。ItemList と BreadcrumbList の構造化データを出す
- データは既存の軽量な一覧（`getCommitteeMeetingListItems`、キャッシュ済み）を絞り込むだけで、Supabase への問い合わせは増やしていない

### URL の決め方（slug）

- `committee-profiles.ts` の各委員会に `slug`（半角小文字・数字・ハイフン）を持たせた。例: 総務文教委員会 → `somu-bunkyo`
- プロフィールに登録していない委員会（新しく設置された特別委員会など）は、委員会名そのものが URL になる
  （`/committees/group/○○特別委員会`）。**新しい委員会の記録を取り込んだら、`committee-profiles.ts` に
  説明・短い呼び名と一緒に `slug` を足す**（足すまでの URL は日本語のまま動く。足したあとは canonical が slug の URL に変わる）
- slug は一度公開したら変えない（URL が変わる）

## あわせて変えたもの

- `/committees` の委員会カード: 「残り N 回の記録を見る」（その場で展開）をやめ、「○○の記録をすべて見る（N回）」のリンクに。
  カードの委員会名もリンクにした
- 会議の詳細ページ: パンくずを 4 段に（TOP > 委員会の記録 > 委員会 > その日の会議）。「一覧へ」も委員会ごとのページへ
- 請願・陳情のカード: 付託先の委員会のリンク先を、一覧のカード（`#committee-…`）から委員会ごとのページへ
- sitemap: 委員会ごとのページ 13 本を追加（更新日は、その委員会の会議の更新日の最大値）
- `/committees/foo` のように会議の ID（UUID）の形でない URL が 500 エラーになっていたのを、404 にした
  （uuid 列に不正な値を渡すとデータベースがエラーを返すため。`isCommitteeMeetingId`）

## 確認したこと

- `pnpm lint`、`pnpm typecheck`、全ワークスペースのテスト、`pnpm --filter web build:ci`、`pnpm smoke:visual`（委員会ごとのページを対象に追加）
- スマホ 375px・PC 1280px のフルページ画像で、一覧・委員会ごとのページ 3 種・会議の詳細を目で確認
- dev サーバーで、13 ページすべて 200・h1 が 1 つ・題名の重複なし・説明 80〜118 字、存在しない slug は 404
