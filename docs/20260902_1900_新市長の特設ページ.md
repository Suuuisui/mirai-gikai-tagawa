# 新市長の特設ページ（/mayor）

## 背景

令和8年7月13日に浦野仁氏が田川市長に就任した。前市長のハラスメント問題→
第三者委員会→退職→市長選という経緯で市民の関心が高く、「新市長が何を
したか」を追いたいという要望があった。既存の `/proposers/mayor`（市長提出
議案の一覧）は歴代の市長提出議案が混在し、新市長の動きだけを追う入口には
ならない。

## 構成

`/mayor` 1ページに次を並べる。上ほど「いま」に近い情報。

| セクション | データ源 | 動的/静的 |
| --- | --- | --- |
| ヒーロー（氏名・就任日・就任N日目・年齢） | 公式プロフィール | 静的＋日付計算 |
| 就任後、議会で何が動いたか | `committee_meetings` の就任日以降 | 動的 |
| 市長が提出した議案 | `bills` の市長提出かつ就任日以降。無ければ次回定例会の予告 | 動的 |
| 就任までの経緯（タイムライン） | 委員会記録の見出し・公式速報 | 静的（リンクは動的解決） |
| 市長選挙・市議補選の結果 | 市の投開票速報 | 静的 |
| 経歴 | 公式プロフィール | 静的 |

トップページの会期バナー直下に導線バナー（`components/top/mayor-banner.tsx`）を
置き、ヘッダー（PC/モバイル）・ハンバーガー・フッターにも「新市長の動き」を
追加した。

## 設計上の判断

- **固定情報の出典は公式に限る**（`shared/data/mayor-profile.ts` に出典URLを
  併記）。出身地・家族など公式プロフィールに無い項目は、ニュース記事に
  あっても載せない
- **タイムラインは会議IDを持たない**。ローカルと本番で `committee_meetings.id`
  が異なる（UPSERTで再作成されると変わる）ため、委員会名＋開催日で
  キャッシュ済み一覧から引く（`createSourceResolver`）。議案も名前で引く。
  解決はローダー（`getMayorActivity`）で済ませ、表示層には解決済みのリンクだけ渡す
- **前市長についてだけの要点は除く**（`pickPointsMatching` + `MAYOR_POINT_PATTERNS`）。
  就任後の記録には「前市長の給料減額条例の廃止」のような文が混じるため。
  要点は素の文字列配列で主語の構造を持たないので、取り込み側で構造を持たせる
  までの暫定フィルタ
- 次の定例会の予告（`UPCOMING_SESSION`）は、就任後の議案が公開されるか、会期が
  DBに登録されて会期中になったら自動で出さない（会期の情報源を二重にしない）
- 就任日 `MAYOR_PROFILE.inaugurationDate` を境に「新市長の動き」を判定する。
  市長が代わったときに直す固有名詞・日付・要点の判定語（`MAYOR_POINT_PATTERNS`）は
  すべて `mayor-profile.ts` に集めてある
- 追加のDBアクセスは無い。`getCommitteeMeetings()` / `getBillsLite()` /
  `getBillsByProposer("mayor")` のキャッシュ済み一覧をフィルタするだけ

## 更新が必要になるとき

- 9月定例会（9/7〜10/8）の議案が `bills` に入れば「市長が提出した議案」に
  自動で並ぶ。予告文（`UPCOMING_SESSION`）はその時点で不要になるので消す
- 市長の任期・会派構成に変化があれば `mayor-profile.ts` を更新する
