# 新市長ページと委員会記録のわかりやすさ改善

## 背景

`/mayor`（新市長の特設ページ）と `/committees`（委員会の記録）を「初めて見る市民」の
目で見直したところ、次の問題があった。

### /mayor

- **「就任後、議会で何が動いたか」が市長の動きになっていない**。就任日以降の委員会記録を
  そのまま並べていたため、「金川線を東鷹高校まで延長」のような市長と関係ない見出しが
  市長ページの一番上に出ていた
- **前市長の話が新市長の動きとして出ていた**。要点から `/浦野|市長/` に当たる文を機械的に
  拾う方式だったため、「令和8年5月の第三者調査委員会報告書で、市長のハラスメントへの責任と
  認識不足が指摘されました」（前市長の話）が新市長の欄に表示されていた
- **これから何があるかが埋もれていた**。9月定例会の予告は「市長が提出した議案」の中の
  注意書きとしてだけ出ていて、「就任後はじめての定例会」という注目点が伝わらない
- **「これまでの市長提出議案をすべて見る」** のリンク先は前市長の議案が大半で、新市長の
  ページからの導線として紛らわしい
- ヒーローの文章が「このページでは〜をまとめています」というページの説明で、
  読む理由（何が分かるか）を先に示せていない。長いページなのにセクションへの
  ジャンプも無い
- 「就任までの経緯」は最も読み応えのある部分だが、見出しが淡白で9項目を読み通す
  前提になっていた。不信任決議の**結果**（否決）も書かれていなかった

### /committees

- 一覧の各行に「中継字幕」「開示文書」の出典表示が並んでいたが、市民が知りたいのは
  出典より「何の話か」。146件中130件が中継字幕なので情報量も無かった
- テーマの絞り込みが画面内の状態だけで、URLに残らない。詳細ページから「同じテーマの記録」へ
  飛べず、絞り込み結果を共有もできない
- 詳細ページは読み終えると行き止まりで、同じ委員会の前後の会議へ進めない
- 「この会議で決まったこと」という見出しの下に要約を出していたが、事務報告だけの会議も
  多く「決まったこと」ではない

## 変更

### /mayor

| セクション | 変更 |
| --- | --- |
| ヒーロー | 就任日・期・年齢を1行に。「就任後に何をしたか／これから何があるか／なぜ交代したか」が分かると先に示し、4セクションへのジャンプナビ（`JumpNav`）を置く |
| 就任後にしたこと | **人が読んで書いた出来事リスト**（`MAYOR_ACTIONS`）に置き換え。就任・就任あいさつ・ハラスメント防止条例の方針・8月臨時会への議案2件・東高校跡地の請願が新市長待ち・9月定例会の20議案、を新しい順に出典リンク付きで並べる。先頭に「最新」バッジ |
| これからの予定と提出議案 | 9月定例会のカードを主役に。「就任後はじめての定例会」「あとN日で開会」（開会後は「会期中（10.8まで）」）と見どころ3点。提出議案が公開されたら同じセクションに並ぶ。一覧へのリンクは「市長提出議案の一覧を見る（前市長の分も含む）」に改名 |
| なぜ市長が交代したのか | 見出しを変え、3行のまとめ（`ROAD_TO_INAUGURATION_SUMMARY`）を先に置く。不信任決議案は議案DBの議決結果（否決）を確認して「2度とも否決」と書き、4/30の項目は議案ページに直接リンク（文章は手書きなので、議案の記録を直したらここも直す） |
| 市長選挙の結果 | 表をやめ、候補者ごとに得票数・得票率・最多得票を基準にした棒グラフで見せる |
| トップのバナー | 「最新: 9月定例会に20議案を提出予定と説明（2026.8.19）」のように、最新の動きを1行で出す |

削除したもの: `filterMeetingsSince` / `pickPointsMatching` / `MAYOR_POINT_PATTERNS` /
`shouldShowUpcomingSession`（要点の機械抽出と、DBの会期と予告の二重化を避ける判定）。
予告カードは会期の日付だけで段階（開会前／会期中／閉会後）を決め、閉会後は消える。

### /committees

- 一覧の行: 出典表示をやめ、暮らしのテーマのチップ（最大2つ）を添える
- テーマの絞り込みを `?topic=` に写す（`routes.committeesByTopic`、クエリ名は
  `COMMITTEE_TOPIC_PARAM`）。選択時は `history.replaceState` でURLだけ更新し
  （履歴は増やさない）、URL→状態の同期は `useSearchParams` を読むだけの
  `TopicUrlSync` に閉じ込める
- 詳細ページ: テーマのチップを「○○の記録」へのリンクにし、末尾に同じ委員会の
  「前の会議／次の会議」と委員会別一覧へのリンクを置く（`findAdjacentMeetings`）。
  要約の見出しは「この会議で何があったか」に変更
- 一覧ページの件数表示は「公式YouTube中継から130回」「開示請求で入手した文書から16回」に

## 設計上の判断

- **市長の動きは機械抽出しない**。要点は主語の構造を持たない文字列で、「市長」が誰を
  指すか判別できない。5〜6件/月の更新頻度なら人が書く方が正確で、文も「何をしたか」の
  形にできる。委員会記録を取り込んだら `MAYOR_ACTIONS` に追記する運用にし、
  `mayor-profile.test.ts` で就任日以降・古い順・見出し30字以内を機械的に守る
- **出典は1項目1つ**。複数の記録にまたがる出来事は、結果が分かる方（議案なら議決結果、
  会議なら当日の記録）にリンクする
- **予告カードは日付で自動遷移**させる。開会前はカウントダウン、会期中はその旨、
  閉会後は非表示。会期が終わったら `UPCOMING_SESSION` を次の定例会に書き換えるか消す
- テーマのURL同期で `useSearchParams` を一覧本体に置かない。静的レンダリングでは
  Suspense 境界までCSRに落ち、一覧が静的HTMLから消えるため、何も描画しない
  `TopicUrlSync` だけを `Suspense` で包んで読む。ヘッダーから `/committees` へ戻る
  ようなソフトナビゲーションでも状態がURLに追従する
- 詳細ページの前後ナビと市長ページの出典リンク解決は、要約を含まない軽量な一覧
  （`getCommitteeMeetingListItems`、`LIST_COLUMNS`）を別キャッシュで持つ。要約入りの
  一覧を詳細ページのたびに読み直すと数百KBになるため

## 更新が必要になるとき

- 委員会記録を取り込んだら、市長に関わる事実を `MAYOR_ACTIONS` に追記する
- 9月定例会の議案が `bills` に入れば「これからの予定と提出議案」に自動で並ぶ。
  10月8日を過ぎると予告カードは消えるので、`UPCOMING_SESSION` を整理する
