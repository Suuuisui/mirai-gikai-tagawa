# 出典の明示と、会議録の取り込み（2026-10-11）

サイトに載せている内容が「何をもとにしているか」を、どのページでも同じ形で分かるようにした。
あわせて、会議録検索システムに新しく公開された本会議の会議録を取り込み、今後は公開を自動で検知する。

## 出典の3区分

| 区分（`SourceKind`） | バッジの名前 | 何の資料か |
| --- | --- | --- |
| `official` | 公式サイト・会議録 | 田川市・田川市議会が公開しているページ・資料と、会議録検索システムの本会議の会議録 |
| `transcript` | YouTube中継の文字起こし | 公式YouTube中継の音声を文字にしたもの（自動字幕。字幕が無い動画は音声認識） |
| `disclosure` | 情報開示請求の文書 | 情報開示請求で交付を受けた文書 |

- 定義: `web/src/features/sources/shared/data/source-kinds.ts`（名前・説明・注意書き）
- バッジ: `web/src/features/sources/shared/components/source-badge.tsx`（Server / Client 共用。色は `globals.css` の `--color-source-*`。色だけに頼らずアイコンと文字を必ず添える）
- 一覧の箱: `source-list.tsx`（「この議案の情報のもと」のように、資料と対象の組を並べる）
- 説明ページ: `/sources`（`features/sources/server/components/sources-page.tsx`）。区分ごとの使いみち（`source-usage.ts`）、会議録の公開範囲、委員会記録の区分ごとの件数、情報開示請求の状況（`DISCLOSURE_STATUS`。**手で更新する**）を載せる

同じ会議に複数の資料があるときの優先順は、公式の会議録 → 開示文書 → 中継の文字起こし。
より正確な資料が手に入ったら記録を作り直し、バッジを付け替える。

### どのページに何を出しているか

| ページ | 出しているもの |
| --- | --- |
| 議案詳細 | 「この議案の情報のもと」（事実と解説を分けて示す）。本文末尾の「## 出典」から読み取る |
| 委員会の記録（一覧） | 行ごとのバッジ、区分ごとの件数 |
| 委員会の記録（詳細） | 見出し下のバッジ、「もとの記録を確認する」に公式の会議録・中継動画へのリンク |
| 請願・陳情 | ページの出典一覧、カードの各部分（原文・本会議の会議録・委員会の記録）のバッジ |
| 一般質問 | 冒頭のバッジ、日ごとの見出しに公式の会議録へのリンク（公開されている日だけ） |
| 選挙の投票率 | セクションごとのバッジ（集計用紙／年代別の表／投・開票速報） |
| 新市長の動き | 項目ごとのバッジ（リンク先の記録の区分） |
| 議員 | 注記の先頭のバッジ |

### 議案の出典の読み取り

議案の本文（`bill_contents.content`）末尾の「## 出典」は seed が書き出している。
書き出し（`buildBillSourceSection`）と読み取り（`parseBillSources`）を
`packages/shared/src/council/bill-source-section.ts` に置き、往復テストで文言のずれを防いでいる。
web は `features/bills/shared/utils/bill-sources.ts` で出典一覧（`SourceRef[]`）に直す。
「## 出典」が無い本文（管理画面で書いた議案）は一覧を出さない。

**文言を変えるとき**: 本番DBの本文が作り直されるまで古い文言が残る。`parseBillSources` を先に両対応にしてから変える。

## 委員会記録の出典種別 `minutes`

`committee_meetings.source_type` に `minutes`（会議録検索システムの本会議の会議録）を足した
（`supabase/migrations/20261011090000_add_minutes_source_to_committee_meetings.sql`）。
画面での区分との対応は `features/committees/shared/utils/committee-source.ts`。

| source_type | 区分 | バッジ |
| --- | --- | --- |
| `minutes` | official | 公式｜会議録 |
| `youtube` | transcript | 文字起こし｜YouTube中継 |
| `disclosure` | disclosure | 開示請求｜開示文書 |

- 会議録がもとの記録は `minutes_text` を持たない（全文はサイトに載せず、会議録検索システムの該当日へリンクする）
- 知らない値は「中継の文字起こし」として表示する（一番注意書きの多い区分に倒す）
- **本番への反映の順番**: 画面のコードを先にデプロイ → 本番DBにマイグレーションのSQLを適用（SQL Editor）→ データを投入。
  古いコードは `youtube` 以外を「開示文書」と表示してしまうため、コードより先に `minutes` の行を入れない

### 記録を、より正確な資料で作り直す

中継の文字起こしをもとにした記録を、会議録（または開示文書）をもとに作り直すときは、
**同じ行を書き換える**（id＝ページのURLを変えない）。投入用JSONのレコードに `replaces_source_type` を付ける:

```json
{
  "committee_name": "本会議",
  "meeting_date": "2026-06-12",
  "source_type": "minutes",
  "replaces_source_type": "youtube",
  "minutes_text": null,
  "source_note": "田川市議会 会議録検索システムで公開されている本会議の会議録をもとにしています。",
  "...": "headline / topics / summary / key_points / agenda_items / attendees / title / youtube_url"
}
```

```bash
DRY_RUN=1 npx dotenv-cli -e <env> -- node scripts/import-committee-meetings.mjs <records.json>   # 置き換える行を確認
npx dotenv-cli -e <env> -- node scripts/import-committee-meetings.mjs <records.json>
curl -X POST https://tagawa-gikai.jp/api/revalidate -H "Authorization: Bearer <REVALIDATE_SECRET>" \
  -H "Content-Type: application/json" -d '{"tags":["committee-meetings"]}'
```

一般質問の日など動画が複数ある記録は、`source_note` の「動画: 名前 URL / 名前 URL」をそのまま引き継ぐ
（詳細ページが動画ごとのリンクにする。`parseSourceNote`）。

## 会議録検索システムの会議録の一覧

- スクレイパー: `pnpm --filter @mirai-gikai/seed tagawa:scrape-minutes-index`
  - 引数なし: 今年と前年だけ取り直す（毎朝の自動更新はこれ。約15リクエスト）
  - `-- --all`: 平成10年から全部（約190リクエスト・5分。初回と、一覧が壊れたときだけ）
  - `-- --years 2025,2026`: 指定した年だけ
- 出力: `packages/seed/tagawa/data/official-minutes.json`（`{ code, records }`）と、
  web 用の `web/src/features/official-minutes/shared/data/official-minutes-data.ts`
- web: `officialMinutesIndex.findByDate(date)` で、その日の会議録を開くURLを引く
  （委員会記録の詳細、一般質問の日ごとの見出し、`/sources` の公開範囲）
- 会議録の本文を取るとき（要約・解説の作り直し）は `scrape.ts` の `supplementFromMinutes` と同じ経路
  （`r_Speakers.exe` → `GetPerson.exe`）。作業用のスクリプトはリポジトリの外（committee-work/minutes2026/）にある

### 公開の検知（毎朝の自動更新）

1. `tagawa:scrape-minutes-index` が一覧を取り直す。増えた日はレポートの「本会議の会議録」に載る
2. `tagawa:find-unrecorded-videos` が本番DBと照らし、会議録が載ったのに `youtube` のままの本会議の記録を
   `<out>/records-awaiting-minutes.json` に書く
3. `tagawa:detect-changes` が、会期の会議録が公開されたのに解説が中継・説明資料をもとにしたままの議案も数える
4. どちらかが残っている間、Issue（`council-update`）に作業として載り続ける

`data/minutes-rework-backlog.json` は、会議録はあるが作り直しを後回しにすると決めた記録を置くためのリスト。
ここに載せた記録は毎日は知らせない。いまは空（2025年2月〜2026年3月の本会議27件を2026-10-11に作り直し、2026-10-13に本番へ入れて外した）。
会議録が出たら作り直すのが原則なので、後回しにする事情があるときだけ使う。

## 自動更新の修正（2026-10-10 に起きた不具合への対処）

公式の「提出議案と議決結果」ページが**会期の途中（最終日より前）に公開された**ため、次のことが起きた。

- 会期中データ（`ongoing-sessions.json`）が会期ごと外れ、最終日に議決される決算6件がサイトのデータから落ちた
- 議員提出議案が公式ページでは「議員提出 議案第62号」と2行で書かれており、読み取りが「議案第62号」になって、
  掲載済みの「議員提出議案第62号」と別の議案として二重に登録された（解説も外れた）

対処（`packages/seed/tagawa/session-data-utils.ts`）:

- `pruneOngoingSessions`: 公式ページに載った議案だけを会期中データから外し、まだ載っていない議案は残す
- `mergeSessions`: 同じ会期が両方にあるときは、公式ページの議案の後ろに未掲載の議案を足す。
  未掲載の議案は `ongoingSourceUrl`（「提出議案」ページ）を持ち、出典もそちらを指す
- `findBillLabelAliases` / `applyBillLabelAliases`: 提出者と番号が同じで表記だけ違う議案は、
  掲載済みの表記を使い続ける（議案の id＝URL は番号表記から決まるため）。
  見つけた読み替えは `data/bill-label-aliases.json` に残り、以後の取り込みでも当たる

会期中の議案を手で置くとき（`ongoing-sessions.json`）は、議員提出議案の番号を「議員提出議案第N号」と書く
（同じ会期に市長提出の「議案第N号」があっても区別できる）。
